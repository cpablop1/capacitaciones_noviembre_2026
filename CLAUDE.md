# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Training-course repository ("capacitaciones noviembre 2026") organized by week: each `SEMANA N/` folder holds that week's independent exercises, built with AI assistance. There is no shared code, package manager, build system or linter; weeks 1–4 are standalone files, and `SEMANA 5/autoventas` (final project) is the only multi-module project with tests. All code, comments, UI text and identifiers are in **Spanish**; keep new work in Spanish. Currency is Guatemalan quetzales (`Q`).

Assignment statements live alongside the code as `.docx`/`.pdf` files, and `.zip` files are submission archives of the same folders — don't edit them.

## Running

Python programs use only the standard library (Tkinter, `json`, `sqlite3`), run directly:

```bash
python "SEMANA 2/farmacia.py"
```

- `SEMANA 1/con_claude`, `SEMANA 1/con_chatgpt`: small console scripts (`input()`/`print()`).
- `SEMANA 1/ejercicios_con_tk_python_IA/ejercicio1-3.py`: Tkinter apps (expenses, guessing game, task manager → `tareas.json`).
- `SEMANA 2/farmacia.py`: Tkinter pharmacy inventory → `inventario_farmacia.json`. Excel export imports `openpyxl` lazily and shows install instructions if missing (`python -m pip install openpyxl`); it's the only optional third-party dependency.
- `SEMANA 3/taxi.py`: Tkinter + SQLite taxi management. `DB_FILE = "taxis.db"` is a **relative path**, so run it from inside `SEMANA 3/` to use the committed database.
- `SEMANA 4/`: static web form (job application). Open `index.html` in a browser; it uses `estilos.css` and `validaciones.js` (all validation is in JS — the form is `novalidate`). `pruebaBug.html` is an unrelated self-contained page (inline CSS) used as a bug-fixing exercise.
- `SEMANA 5/autoventas/`: final project "AutoVentas" (car sales), built twice from the same design (`SEMANA 5/Proyecto final - HIA.pdf`):
  - `escritorio/`: Python + Tkinter (`ttk.Notebook`, 4 tabs). Run `python main.py`; tests `python -m unittest discover -s pruebas -t . -v` (single test: `python -m unittest pruebas.test_autoventas.CasosDePruebaMinimos.test_cp05_venta_correcta`). Data in `escritorio/datos/autoventas.json` (git-ignored).
  - `web/`: HTML/CSS/vanilla JS, opened directly as `index.html` (no server, no dependencies; data in `localStorage`). Tests `node --test` from `web/` (single test: `node --test --test-name-pattern="CP-05"`).
  - `documentacion/`: Word deliverable generated by `fuente/generar_documento.js` (docx-js); regenerate it instead of editing the `.docx` by hand.

## AutoVentas: keeping the two versions in sync

The web version is a direct translation of the desktop one, layer by layer: `validaciones.py`↔`js/validaciones.js`, `logica.py`↔`js/logica.js`, `persistencia.py`↔`js/persistencia.js`, `interfaz.py`↔`js/interfaz.js` + `index.html`, `main.py`↔`js/main.js`. Business rules, error messages, the JSON data format (field names like `anio`, `id_auto`, `porcentaje_descuento`) and the 37 tests are identical in both, so any rule change must be made in both versions and both test suites. The UI layers never validate or calculate; they call the logic layer, which raises `ErrorValidacion` (with `errores` list and, in JS, a `campos` map for inline field errors) or `ErrorNegocio` for blocked operations. Every mutating operation runs inside `_transaccion`, which rolls back in-memory data if saving fails. In the web UI, user data is inserted with `textContent` only (never `innerHTML`). JS modules use a small UMD-style wrapper (`window.AV.*` in the browser, `module.exports` in Node) so they work from `file://` and in `node --test`.

## Architecture conventions

The larger Tkinter apps share a pattern worth preserving:

- **Logic separated from UI.** Validation, search, sorting, CRUD and load/save are plain module-level functions with no Tkinter dependency (so they can be tested directly), and a single class (`AppInventario(tk.Tk)`, `AdministradorTareas`, `App(tk.Tk)`) builds the interface and calls them.
- **Persistence next to the script.** JSON data files are resolved relative to `__file__` and saved automatically after every add/edit/delete; loading tolerates missing or corrupt files. `farmacia.py` stores `{"tema": ..., "productos": [...]}` and writes atomically via `tempfile`.
- **Custom styling.** Each app defines its own color palette and fonts as constants (e.g. `COLORES`, `BG`/`ACENTO`) and applies them through `ttk.Style`; reuse those constants instead of hard-coding colors.
- `taxi.py` wraps SQLite in a `Database` class (`PRAGMA foreign_keys = ON`, `sqlite3.Row`), and the UI is a sidebar with `Pagina` subclasses (Inicio, Taxis, Conductores, Viajes). Fares come from `calcular_tarifa(km)` = `TARIFA_BASE + TARIFA_KM * km`.
